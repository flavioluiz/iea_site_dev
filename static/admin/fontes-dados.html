A atualização exige acesso autorizado ao Scopus pela rede/VPN do ITA. Credenciais nunca devem ser colocadas no site público.

  1. Um mantenedor abre o workflow no repositório privado iea_data_automation.
  2. Executa primeiro uma coleta de teste (dry run) e confere o relatório.
  3. Executa a carga completa; a proposta só é publicada após os testes e a revisão.

Importante: o modo “Somente testar” vem marcado. Ele coleta e confere os dados, mas nunca altera o site nem abre uma proposta.

  1. Um mantenedor abre Atualizar dados da Biblioteca.
  2. Executa com Somente testar marcado e confere o relatório.
  3. Se o teste estiver correto, executa novamente com Somente testar desmarcado. Isso abre uma proposta, mas ainda não altera o site.
  4. Confere os testes da proposta e usa Merge pull request. Só então o site começa a ser publicado.

Pessoas, laboratórios, departamentos, projetos, páginas e documentos são atualizados diretamente pelo editor. Eles não têm uma “última sincronização” coletiva: cada alteração passa pelo fluxo de revisão e publicação.
